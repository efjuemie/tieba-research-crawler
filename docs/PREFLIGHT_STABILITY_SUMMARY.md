# 正式采集前稳定性验收摘要

更新：2026-11-16。最终分页复测与回归结果已纳入。

**总体判断：2021—2026 年普通主题与精华主题双流全量采集仍为 INCONCLUSIVE，不建议现在启动以完整覆盖该时段为前提的正式采集。** 隔离恢复、数据库回归和多数恢复场景已通过；两条 CREATE 流的实际响应均触发严格排序检查并保持失败／不完整。该结论描述本轮响应，不代表贴吧服务永久不可达，也没有证据表明主题身份被错误关联。

## 分页结果

- **普通主题流**：第 1–70 页连续通过，最后成功页最早主题日期为 2026-05-05。第 71 页请求和响应页号一致，响应含 28 条唯一主题记录。按 API 返回／解析的置顶标记处理后，页内创建时间仍有约 20 分钟逆序；raw 与 DTO 时间顺序一致，没有解析回退或转换差异。程序将该页记为失败／不完整，没有跳过或标为完成。受控重放的页面指纹与首次失败相同，确认该次逆序不是一次性变化；本轮真实请求已停止。该流尚未到达 2021 年。
- **精华主题流**：第 1 页最早到达 2016 年；第 2 页重放仍出现跨页创建时间回跳，虽然该页内部排序正常，程序仍将其记为失败／不完整。该流能否完整到达 2021 年尚未证明。

这些页数是主题列表发现与持久化检查结果；本轮没有为相应页面运行完整的详情或网页补采工作器。这不表示已采齐这些主题的首楼、回复、楼中楼或正文，也没有导出新的正式研究语料。

普通流第 71 页的原始响应和 DTO 中，28 条记录的 `is_top` 解析值均为 false。该字段是没有 presence 证明的 protobuf 标量，因此这里只报告接口返回／解析值，不将其当成逐条网页核验过的置顶结论。

分页异常说明这些响应不满足当前严格的创建时间排序条件。程序没有放宽校验、跳过异常页或将其标作正常结束。

## 已通过的稳定性检查

- 基线 HEAD `4db3217` 的全仓测试为 **640 passed、10 skipped**。本轮修改后的最终全仓回归为 **654 passed、10 skipped、18 warnings**；定向合成测试为 **22 passed、4 skipped**。
- 两组隔离 PostgreSQL 回归均通过：scope 测试 2 passed，runtime 测试 2 passed。测试夹具调整后，相关隔离表没有遗留行；夹具适配没有引入其他生产逻辑变化。
- R1–R3 隔离 PostgreSQL／模拟 API 演练通过。SIGINT 发出后，已接收的第 3 页完成提交；同一 run 恢复时重放最近完成的非终止第 3 页，再推进到第 4 页。两条 CREATE 流的独立检查点和规范 ID 去重通过；checkpoint 提交前注入故障后重试通过。
- 为避免恢复时选择不同运行模式的 run，恢复查询现在会按模式筛选。该跨模式问题在隔离 PostgreSQL 中复现并确认被拒绝；本轮生产源码只改了这一项条件。独立最终复审覆盖 4 个代码文件，未发现阻断问题。
- 一个历史 PID 错配样本的当前网页候选通过只读身份检查：主题、楼层、评论、父楼、作者和论坛等 8 项标识一致；规范数据未写入，内容哈希未变。此结果只覆盖一个 `web_network` 候选路径，不能代表所有旧样本或所有网页来源类型。
- 两条历史楼中楼异常抽样的当前 API 响应中，TID／PID／FID 身份匹配；返回总数为 0 且 `has_more=false`。这无法还原旧分页异常的根因，原有 incomplete 状态继续保留；另外 8 条本轮没有重新请求。
- IDE 图形界面的 Stop 和强制结束没有现场验证。R1 的终端 SIGINT 恢复演练不能代表这两种停止方式。

## 数据保护与恢复

隔离数据库备份恢复验证通过。只读最终对照通过：原始三个数据库保持不变；指定 V5 的 13 个 CSV 与 manifest 的哈希、字节数和行数均与基线一致。该结论不涵盖含合成演练记录的隔离验收副本。公开摘要不公布哈希或采集标识。本轮没有启动新的正式采集或导出新的正式研究语料，真实请求已停止。

恢复自己的既有回溯 run 时，使用相同论坛范围和运行模式，并填入本机日志中的 run ID：

```sh
uv run python main.py --mode backfill --resume --run-id YOUR_RUN_ID
```

这里的命令只适用于此前以 `backfill` 模式创建的 run。当前恢复、隔离数据库和回归检查已有通过结果；双流到 2021 年的完整可达性仍未证明，因此不建议现在启动以 2021—2026 全量完整为前提的正式采集。
